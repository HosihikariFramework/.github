# Contributing

Thanks for helping the Hosihikari Framework. These rules apply to every repository in the
organization unless that repository has its own `CONTRIBUTING.md`.

## Before opening a pull request

- Search existing issues and the [documentation](https://hf.srcz.one/).
- Use the issue templates for bugs, feature requests, and documentation problems.
- For a large API, lifecycle, or architecture change, open an issue first and link the relevant
  [ADR](https://github.com/HosihikariFramework/Design).
- Do not include secrets, credentials, personal data, or a copied game server in a commit.

## Workflow

1. Work on a branch. Public default branches are protected; direct pushes are rejected.
2. Follow the repository's `AGENTS.md` for build, test, and verification commands.
3. Keep the change focused; update tests, documentation, and the glossary or ADR when behavior or
   terminology changes.
4. Fill in the pull request template and describe the verification you ran.
5. Wait for review, then squash merge.

## Language and docs

- English is the primary language for the documentation site; Chinese pages live under `/zh/` and
  must stay in sync.
- Match the language already used in the repository for commit messages and code comments.
